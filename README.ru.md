# Echo — языковая модель на жидких нейронных сетях (LTC / CfC)

[English](README.md) | [Русский](README.ru.md)

**Echo (Эхо)** — первая модель планируемого семейства **Pantheon**.
[План названий](NAMING.md) сохраняет будущую иерархию и правила версий.

Авторегрессионная языковая модель на **жидких нейронных сетях** (Liquid
Time-Constant и Closed-form Continuous-time) на PyTorch. Код организован в
пакет `liquid_lm`: загрузка и очистка корпуса, токенизаторы, модель, обучение,
генерация, чат и вспомогательные утилиты. Запуск идёт через тонкую точку входа
`liquid_text_model.py` (или `python -m liquid_lm`), поэтому все команды из
этого документа работают из корня репозитория.

Вместо self-attention модель обрабатывает текст рекуррентно: скрытое состояние
каждого слоя эволюционирует как динамическая система с обучаемыми временными
константами. Это даёт память фиксированного размера и стоимость генерации,
линейную по длине последовательности.

> Текущая версия: **v3.8**. История изменений — в конце документа.

## Возможности

**Модель**

- Два типа ячеек: экспоненциальные ODE-обновления по мотивам **LTC** и
  интерполяция по мотивам **CfC** (Hasani et al., 2022).
- **Multi-tau**: банки быстрых, средних и медленных временных констант,
  смешиваемые обучаемым softmax.
- Один плотный экспоненциальный шаг при каждом проходе через ячейку; доступен Triton.
- Экспериментальные повторные проходы через общие веса (`--recurrent-passes`,
  по умолчанию 1): отдельные состояния во времени без новых параметров.
- Причинная depthwise-свёртка (`k=5`) перед liquid-ядром, переносящая контекст
  между чанками и шагами генерации.
- Residual-связи, встроенный RMSNorm на выходе ячейки, zoneout и locked-dropout на
  эмбеддингах.
- Необязательная **привязка весов** (weight tying) между эмбеддингом и
  выходным слоем и необязательная MLP-голова.
- **Компактная ChunkMemory**: FIFO-история с флагами заполнения, узкими
  проекциями и управляемым чтением на границах чанков. Новое обучение
  использует три слота и ширину проекции 64.

**Данные**

- Форматы: `.txt .md .rst .log .csv .tsv .json .jsonl .parquet`.
- Автоопределение кодировки (`charset-normalizer`, запасной путь через
  `utf-8 → cp1251 → cp1252 → latin-1`).
- Автоматическое приведение диалоговых датасетов (`messages`,
  `conversations`, `instruction/output`, `question/answer` и других) к
  единому формату с тегами ролей.
- Дедупликация файлов по хэшу содержимого, детерминированное перемешивание
  файлов и ограничение размера файла.
- Byte-level BPE (`tokenizers`) и посимвольный токенизатор.

**Обучение**

- Truncated BPTT с переносом состояния между подчанками (`--state-carry`).
- Накопление и клиппинг градиентов, косинусное расписание с прогревом.
- AdamW (fused на CUDA) и гибрид Muon + AdamW.
- EMA-веса и автоматический выбор лучших весов (обычных или EMA) по
  валидации.
- Смешанная точность (bf16 / fp16 с GradScaler), `torch.compile` для
  рекуррентного шага и gradient checkpointing.
- Маскирование лосса: для диалогов в лосс входят только ответ бота и маркер
  конца примера.
- Диалоговые якоря: часть окон батча начинается ровно с `<|user|>`.
- Дистилляция знаний (KD) из чекпоинта-учителя.
- Необязательное логирование в TensorBoard / Weights & Biases.
- Возобновление с восстановлением оптимизатора, планировщика, EMA и scaler.

**Инференс**

- Сэмплирование с temperature, top-k, top-p и штрафом за повторы.
- Разовые запросы в режиме чата и интерактивный REPL с историей.
- Необязательные CUDA Graphs для полного шага генерации, включая границы
  ChunkMemory, с ограниченным переиспользуемым кэшем и откатом на eager.
- Необязательные fused Triton-ядра для активаций и хвоста LTC-подшага: инференс и
  экспериментальный backward первого порядка при обучении на CUDA.

## Требования и установка

**Обязательно**

- Python **3.9+**
- `torch` (рекомендуется 2.x; для `torch.compile` нужен 2.0+)
- `numpy`

**Необязательно**

| Пакет | Назначение |
|---|---|
| `tokenizers` | BPE-токенизатор (без него программа переходит на char) |
| `pandas` + `pyarrow` | Чтение `.parquet`, `.csv` и `.tsv` как таблиц |
| `charset-normalizer` | Точное определение кодировки текстовых файлов |
| `tensorboard` | Логирование с `--log-backend tensorboard` |
| `wandb` | Логирование с `--log-backend wandb` (нужен `wandb login`) |
| `triton` | Fused LTC Euler для инференса/обучения; на Windows также проверена совместимая сборка `triton-windows` |

```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate

# Установи PyTorch по инструкции на pytorch.org для своей версии CUDA
pip install torch numpy

# Рекомендуемый минимум для реальной работы
pip install tokenizers pandas pyarrow charset-normalizer

# Необязательно
pip install tensorboard wandb
```

Проверь, что GPU виден:

```bash
python -c "import sys, torch; print(sys.executable); print(torch.__version__, torch.version.cuda); print('CUDA:', torch.cuda.is_available())"
```

для запуска на GPU. CPU-сборка не сможет использовать CUDA, даже если драйвер
видит видеокарту. CLI при старте печатает устройство, GPU, VRAM и настройки
Tensor Cores.

## Быстрый старт

Датасеты и обученные checkpoints не входят в репозиторий. Перед обучением
подготовь свой корпус.

1. Положи текстовые файлы в `data/` (подпапки поддерживаются):

   ```
   data/
   ├── books/
   │   ├── book1.txt
   │   └── book2.txt
   └── dialogs.jsonl
   ```

2. Запусти обучение с настройками по умолчанию:

   ```bash
   python liquid_text_model.py --data data
   ```

3. Сгенерируй текст лучшей моделью:

   ```bash
   python liquid_text_model.py --generate-only --prompt "Once" --generate 500
   ```

4. Поговори с моделью (если она обучалась на диалогах):

   ```bash
   python liquid_text_model.py --chat-repl
   ```

> Минимальный размер корпуса — **1000 символов** (`--min-chars`). Для
> осмысленной генерации нужны мегабайты текста; корпус в несколько килобайт
> годится только как smoke-тест.

## Подготовка данных

### Поиск файлов

Программа рекурсивно сканирует `--data` и выбирает файлы с поддерживаемыми
расширениями. Она игнорирует `.git`, `__pycache__`, `node_modules`, `.venv`,
`venv`, `.idea`, `.vscode`, `.mypy_cache` и `.pytest_cache`.

Если папки не существует, она создаётся, и программа сообщает, что корпус
пуст.

### Обработка каждого файла

1. Пропускаются файлы больше `--max-file-mb` (при значении > 0) и пустые
   файлы.
2. Файл читается в соответствии с форматом.
3. Текст очищается: нормализуются окончания строк (`\r\n`, `\r` → `\n`),
   обрезаются пробелы в конце строк, 3 и более пустых строк подряд
   схлопываются в одну пустую.
4. Файлы с идентичным очищенным содержимым дедуплицируются.
5. Корпус склеивается. С `--file-headers` между файлами вставляются строки
   `===== filename =====` (по умолчанию выключено).

Итоговая статистика включает найденные и использованные файлы, размер по
расширениям, пропущенные файлы (слишком большие, пустые или дубликаты) и
файлы, прочитанные с неуверенным определением кодировки.

### Поддерживаемые форматы

| Расширение | Как читается |
|---|---|
| `.txt .md .rst .log` | Сначала UTF-8 (BOM удаляется), затем определение кодировки и резервные варианты |
| `.json` | Список или объект; диалоговые структуры превращаются в текст с тегами, иначе текст извлекается из `text/content/article/body/document` |
| `.jsonl` | Одна JSON-запись на строку; действуют те же правила, нераспознанные строки добавляются как есть |
| `.csv .tsv` | Через pandas; колонки «вопрос–ответ» становятся диалогом, иначе используется текстовая колонка |
| `.parquet` | Так же, как таблицы (нужны `pandas` + `pyarrow`) |

Без `pandas` CSV/TSV читаются как обычный текст, а Parquet-файлы
пропускаются.

JSON и JSONL поддерживают UTF-8 BOM. Невалидный UTF-8 в JSONL вызывает ошибку
вместо незаметного удаления байтов; такие файлы нужно перекодировать в UTF-8.
Исключённые каталоги отсекаются до обхода их содержимого.

При обучении int32-токены целиком хранятся на выбранном устройстве. Исходный
текст и временные int64-ID освобождаются после подготовки. Загрузка остаётся
полностью в памяти: большим корпусам нужен соответствующий объём RAM/VRAM.

### Формат диалогов

Диалоги нормализуются к четырём служебным тегам:

| Тег | Значение |
|---|---|
| `<\|user\|>` | Реплика пользователя |
| `<\|bot\|>` | Ответ бота |
| `<\|system\|>` | Системная инструкция |
| `<\|end\|>` | Конец примера |

Пример:

```
<|user|>
What is a liquid neural network?
<|bot|>
It is a recurrent network whose state is described by a differential equation.
<|end|>
```

Распознаваемые входные структуры:

**Список сообщений** (датасеты в стиле OpenAI):

```json
{"messages": [
  {"role": "system", "content": "Answer briefly."},
  {"role": "user", "content": "Hello"},
  {"role": "assistant", "content": "Hello!"}
]}
```

**Формат `conversations`** (в стиле ShareGPT):

```json
{"conversations": [
  {"from": "human", "value": "Hello"},
  {"from": "gpt", "value": "Hello!"}
]}
```

**Пары «вопрос–ответ»** проверяются в таком порядке:

| Ключ вопроса | Ключ ответа |
|---|---|
| `instruction` | `output` |
| `instruction` | `response` |
| `question` | `answer` |
| `prompt` | `response` |
| `prompt` | `completion` |
| `input` | `output` |

Если рядом есть непустое поле `input` (формат Alpaca), оно добавляется к
вопросу с новой строки.

Соответствие ролей: `user`, `human` → `<|user|>`; `assistant`, `gpt`, `bot`,
`model` → `<|bot|>`; `system` → `<|system|>`. Неизвестная роль считается
пользователем.

### Разделение на train / validation

- В новых BPE-запусках `--val-split` выбирает валидационный **хвост текста по
  числу символов** (по умолчанию `0.1`, допустимо `0.01–0.5`). BPE обучается
  только на train-префиксе; части кодируются отдельно. Доли токенов могут отличаться.
- Char сохраняет разбиение по токенам и словарь всех символов корпуса.
- Чтобы хвост не состоял систематически из последних по алфавиту файлов,
  `--shuffle-files` включён по умолчанию. Файлы упорядочиваются по SHA-256
  от относительного пути, детерминированно.
- Обе части должны быть длиннее `seq_len × state_carry + 2` токенов.
- Политика разбиения хранится в конфигурации чекпоинта (`data_split_policy`).
  При возобновлении старого чекпоинта без этого поля остаётся прежняя граница
  по токенам. Граница всё ещё может разрезать документ или диалог; разделение
  по записям и удаление близких дубликатов пока не реализованы.

## Токенизаторы

### BPE (`--tokenizer bpe`, по умолчанию)

- Byte-level BPE: любой символ Unicode кодируется без `<unk>` (все 256 байт
  есть в словаре).
- Пробельный префикс отключён: текст кодируется и декодируется без
  добавленных пробелов.
- Специальные токены: `<unk>`, `<pad>`, `<|user|>`, `<|bot|>`, `<|system|>`,
  `<|end|>`.
- Размер словаря задаётся `--vocab-size` (по умолчанию 8000, минимум 300). Для
  малых корпусов он автоматически уменьшается: потолок равен
  `max(300, estimated_tokens / 20)`, где `estimated_tokens = символы / 4`.
- Большие корпуса кодируются чанками примерно по 2 миллиона символов с
  разбиением по границам `\n\n`, чтобы ограничить расход памяти.
- Без библиотеки `tokenizers` программа переходит на char и сообщает об этом.

### Char (`--tokenizer char`)

- Словарь содержит каждый различный символ всего корпуса, а не только
  обучающей части.
- Неизвестные при инференсе символы заменяются пробелом.
- Теги диалогов не являются отдельными токенами, поэтому маскирование лосса,
  диалоговые якоря и стоп-токены **не работают**. Для диалогов используй BPE.

Токенизатор хранится внутри чекпоинта; отдельные файлы словаря не нужны.

## Архитектура модели

### Общая структура

```
tokens
  │
  ▼
Embedding ──► LockedDropout
  │
  ▼
[опционально] причинная depthwise-свёртка k=5  (x = x + conv(x))
  │
  ▼
┌──────────────── для каждого шага t ────────────────┐
│  слой 1: LiquidCell(h1, x_t) ──► h1'               │
│  x = x + h1'     (residual, если включён)           │
│  слой 2: LiquidCell(h2, x)  ──► h2'               │
│  x = x + h2'                                        │
│  ...                                                │
│  финальный RMSNorm(x)                               │
└─────────────────────────────────────────────────────┘
  │
  ▼
Readout (Linear или MLP-голова; веса можно привязать к Embedding)
  │
  ▼
logits (vocab_size)
```

Время обрабатывается в цикле Python: состояние каждого слоя обновляется по
одному токену. Проекции, зависящие только от `x` (но не от `h`), считаются
один раз на всю последовательность до начала цикла.

### Повторные проходы через общие веса

`--recurrent-passes 2` выполняет liquid-стек дважды для каждого токена.
У каждого прохода отдельные состояния во времени; веса ячеек и обучаемые
начальные состояния общие. FFN выполняются только на последнем проходе.
ChunkMemory читает и записывает последний рекуррентный поток, а причинная
свёртка выполняется один раз перед стеком. Для нескольких проходов размеры
эмбеддинга и скрытого состояния должны совпадать. Значение по умолчанию 1
сохраняет прежние уравнения и набор параметров.

Это дополнительная вычислительная глубина, а не ODE-подшаги или доказанная
способность рассуждать. Число проходов сохраняется в чекпоинте; его изменение
при генерации меняет семантику модели и не является поддерживаемой конверсией.
Перед включением сравнивайте качество на отложенных данных и затраты вычислений.

### LiquidCell — режим `ltc` (по умолчанию)

Ячейка моделирует динамику по мотивам LTC с временной константой,
зависящей от входа и состояния:

```
dh/dt = (candidate − h) / τ
candidate = tanh(W_x·x + W_h·h)
τ         = softplus(MLP([x, h])) + min_tau        (min_tau = 0.05)
```

Внутри подшага `candidate` и `τ` «замораживаются», и ODE решается точно:

```
decay = exp(−dt / τ)
h_new = decay · h + (1 − decay) · candidate
```

При `dt >= 0` и `τ > 0` это замороженное обновление является выпуклой смесью
старого состояния и кандидата. Это свойство само по себе не доказывает
устойчивость всей нелинейной рекуррентной сети с нормализацией и residual-связями.

Кандидат и временная константа вычисляются один раз на токен. Используется
экспоненциальное обновление с замороженными коэффициентами.

**Multi-tau (`--multi-tau`, включён по умолчанию).** Выход `tau_net`
утраивается в три банка:

| Банк | Формула | Смысл |
|---|---|---|
| fast | `softplus(r₀ − 2) + 0.05` | Быстрая динамика |
| medium | `softplus(r₁) + 0.01` | Средняя динамика |
| slow | `softplus(r₂ + 2) + 0.001` | Больший начальный сдвиг |

Итоговое `τ = Σ wᵢ · τᵢ`, где `w = softmax(tau_mix)` — три обучаемых
глобальных (не по каналам) веса. Банки дают одну эффективную константу на
канал и используют общее рекуррентное состояние. Это не независимые состояния
памяти; порядок констант и долгая память после обучения не гарантированы.

### LiquidCell — режим `cfc`

Интерполяция по мотивам Hasani et al., *Closed-form Continuous-time Neural
Networks* (Nature Machine Intelligence, 2022). В авторской
[реализации](https://github.com/raminmh/CfC/blob/main/torch_cfc.py) перед
кандидатами и временными головами стоит общий нелинейный backbone. Здесь
используются прямые проекции `[x, h]`, поэтому это упрощённый вариант.
Численного ODE-решателя в этой ветке нет.

```
ff1 = tanh(W₁ₓ·x + W₁ₕ·h)
ff2 = tanh(W₂ₓ·x + W₂ₕ·h)
t   = sigmoid(t_a · dt + t_b)           # t_a, t_b — функции от [x, h]
h_new = ff1 · (1 − t) + t · ff2
```

Здесь меньше индуктивного смещения в сторону затухания и больше свободы
формы траектории. `--multi-tau` в этом режиме игнорируется (нет ни `τ`, ни ODE). `time_net.bias` начинается с нуля; `t = 0.5` получается
при нулевом суммарном входе sigmoid, а не для любого входа при инициализации.

### Выход ячейки и нормализация состояния

Новое состояние слоя — `RMSNorm(Dropout(h))`. RMSNorm — единственная поддерживаемая
нормализация в ячейках, FFN и перед выходом: обучаемый масштаб без смещения и
вычитания среднего. Для FP16/BF16 статистики вычисляются в FP32. Состояние между
временными шагами **нормализовано**, поэтому от этого зависит рекуррентная динамика.
Параметр CLI `--norm-type` удалён.

Новые чекпойнты явно сохраняют `norm_type: rms`. Чекпойнты LayerNorm, включая старые
файлы без указания нормализации, отклоняются при resume и генерации. Для этих весов
нужна предыдущая версия проекта либо новое обучение RMSNorm-модели. Изменение
метаданных или удаление смещений не конвертирует обученные веса.

При отборе функций качество на отложенных данных важнее времени вычислений.
Более дорогие варианты стоит сохранять, когда контролируемое обучение
подтверждает улучшение качества.

**Zoneout (`--zoneout`).** Во время обучения часть элементов выхода
заменяется нормализованным предыдущим состоянием, что регуляризирует резкие
изменения состояния.

### Локальная причинная свёртка (`--local-conv`)

Depthwise `Conv1d` с ядром 5 добавляет к эмбеддингам локальный контекст из
четырёх предыдущих токенов: `x = x + conv(x)`.

Свёртка строго причинная: паддинг только слева, поэтому позиция `t` зависит
от `x[t−4..t]`. Симметричный паддинг раскрыл бы будущие токены и привёл бы к
утечке ответа в лосс. Последние четыре входа хранятся в **буфере свёртки**,
который переносится как дополнительный элемент `hidden`, так что контекст
продолжается через границы чанков и при посимвольной генерации.

### Residual-связи, привязка весов и голова

- `--residual` (включён): `x = x + h_new` после каждого слоя. Для первого
  слоя это работает только при `embedding_dim == hidden_size`.
- `--tie-weights` (включён): выходной слой использует матрицу эмбеддингов.
  Требует `embedding_dim == hidden_size`.
- `--mlp-head` (выключен): заменяет один `Linear` на `Linear → GELU → Linear`.
- Начальные состояния `h0` обучаются, по одному параметру на слой.

### Компактная ChunkMemory (`--memory-slots N`, `--memory-dim D`)

Новое обучение через CLI использует RMSNorm, три слота памяти, проекции шириной 64 и
четыре чанка с переносом состояния. Слот хранит отсоединённое конечное состояние
чанка и флаг заполненности. Пустые слоты исключаются из чтения; полностью пустая
память точно сохраняет входное состояние. Проекции обучаются при чтении.

При H384/D64 модуль добавляет **106 624 параметра**, прежний — **738 432**.
Размеры последней модели с RMSNorm, компактной памятью и прежним FFN дают
**4 641 542 параметра**. Это подсчёт размера, а не доказательство улучшения речи.

- `--memory-slots 0` отключает память; `--memory-dim 0` выбирает прежний формат.
- Четыре чанка дают до трёх предыдущих сводок. Для большего числа слотов нужны
  более длинные обучающие последовательности.
- Градиент обрывается на границах чанков: его горизонт равен `seq_len`, прямой
  контекст равен `seq_len * state_carry`.
- При генерации память читается/обновляется на границах сохранённого `seq_len`
  и сбрасывается для каждого запроса.
- Чекпойнты RMSNorm без `memory_dim` загружают прежний формат памяти.
  Для LayerNorm нужна предыдущая версия; обученные веса не переводятся
  автоматически на новые настройки.

### Ассоциативная память с записью по ошибке (эксперимент)

`--innovation-memory-dim 32` добавляет матрицу состояния 32×32 рядом с жидким
ядром, перед финальной нормализацией и выходной проекцией. Слои LTC/CfC по-прежнему
обрабатывают каждый токен. Память читает старые ассоциации «ключ → значение»,
затем записывает поправку к ошибке собственного предсказания. Энергия этой ошибки
модулирует обучаемую скорость записи. У каждого канала значения своя обучаемая
скорость затухания с начальными горизонтами от 32 до 1024 токенов.

Это экспериментальное сочетание идей [LTC](https://arxiv.org/abs/2006.04439)
и [delta-памяти](https://arxiv.org/abs/2412.06464) для проекта, без заявления
научного приоритета. Здесь нет softmax-внимания или растущего кеша токенов.
Чтение происходит **до** текущей записи. Матрица накапливается в FP32 при AMP,
переносится и отсоединяется от графа вместе с остальным состоянием. Работает
при обучении, генерации и в чате; сбрасывается с началом новой последовательности.

Значение `0` по умолчанию отключает модуль и сохраняет поведение старых checkpoints.
Для включения нужно обучить модель с новыми параметрами: флаг не добавляет
обученную память в старый checkpoint при генерации. При H=384, D=32 добавляются
62 659 параметров и 4 КиБ текущего состояния на пример. Активации BPTT и состояние
оптимизатора требуют дополнительной памяти. Сам модуль пока использует PyTorch,
в том числе с Triton-ядром LTC; стоимость шага нужно измерять.

```bash
python liquid_text_model.py --data data --innovation-memory-dim 32
python benchmark_innovation.py --device cpu --steps 800 --seeds 11 22 33
```

Синтетический тест сравнивает LTC, контроль с FFN и ассоциативную память при
одинаковых общих весах, обучающих батчах и отложенных запросах. Это проверка
памяти, а не качества языка; внешний датасет не используется.

После 800 обновлений на вариант и трёх seed средняя точность составила:

| Модель | 8 отвлекающих токенов | 32 | 64 |
|---|---:|---:|---:|
| LTC, 32 798 параметров | 23,70% | 15,56% | 12,11% |
| LTC + FFN, 37 534 параметра | 21,68% | 16,73% | 15,49% |
| LTC + память, 38 145 параметров | **36,85%** | **32,94%** | **27,93%** |

Обучение использовало восемь отвлекающих токенов; большие задержки проверяют
перенос. Случайный выбор среди восьми значений даёт 12,5%. На обученной задержке
память превзошла оба контроля на всех трёх seed, но длинные задержки дали большой
разброс. При одинаковом числе обновлений она использует больше вычислений:
преимущество в языке или при одинаковом времени пока не установлено. Небольшой
замер на RTX 5050/Triton дал медианы шага 37,98 / 42,57 / 128,07 мс соответственно
(B=64, H=64, T=22, 30 шагов).

В том же тесте с 800 обновлениями обычная delta-запись получила 43,49% на задержке
8 и 37,17% на задержке 256, а gate по энергии ошибки — 36,85% и 20,96%.
Добавленный gate пока не подтвердил преимущество.
При 30 секундах обучения на seed на RTX 5050 средняя точность на задержке 8
составила 23,31% для LTC, 18,29% для нашей памяти и 29,04% для обычной delta.
Большой разброс скорости ограничивает выводы этого небольшого сравнения по времени.

Последующая проверка на «Алисе в Стране чудес» **не подтвердила** пользу для языка:
после 300 обновлений средняя по трём seed ошибка на отложенном тексте составила
1,9575 для LTC, 1,9885 для этой памяти и 1,9843 для обычной delta-записи
(character NLL, меньше — лучше). Это новые маленькие модели со словарём только
по train и разбиением 80/10/10, без выбора весов по validation/test.
Эксперимент остаётся отключённым по умолчанию; контроли и ограничения описаны
в CONTRIBUTING.

### Инициализация

Эмбеддинги — `N(0, 0.02)`; рекуррентные матрицы ортогональные с `gain=0.99`;
входные проекции — Xavier; смещения нулевые, если не указано иное. `h0`
инициализируется нулями и обучается. Для `ltc` `tau_mix` стартует равномерно, а
временная сеть инициализируется так, чтобы стартовая динамика была
устойчивой и умеренно медленной.

## Как устроено обучение

### Автономные запуски

`echo_jobs.py` выполняет заранее заданный сценарий отдельным локальным
контроллером, без опросов со стороны агента и вызовов LLM/API. Подготовьте
корпус и проверьте
[`examples/unattended_training.json`](examples/unattended_training.json)
перед запуском. Пример использует CUDA/BF16/Triton, выбирает веса по validation
и затем генерирует текст по фиксированному промпту. Отдельная оценка на тестовой
выборке в пример не включена.

```bash
python echo_jobs.py launch --recipe examples/unattended_training.json --run-dir runs/echo_unattended_01
python echo_jobs.py status runs/echo_unattended_01
python echo_jobs.py result runs/echo_unattended_01
python echo_jobs.py stop runs/echo_unattended_01
```

Команда запуска подтверждает старт контроллера и завершает работу. Этапы
выполняются последовательно в отдельных подпапках; существующая папка запуска
не перезаписывается. Сохраняются `recipe.json`, `status.json`, `result.json`,
`report.md`, логи этапов и чекпоинты. Команды статуса/результата используют
только стандартную библиотеку. Если работа ещё идёт, `result` возвращает код 2.
Итоговый JSON содержит сводки этапов и ограниченные хвосты логов — результат
можно забрать одним последующим обращением.

Трёхчасовой бюджет примера включает пять минут на завершение и две минуты
на штатную остановку. Запрос остановки обучения поступает за семь минут до
общего дедлайна. Штатное обучение проверяет его на границе эпохи, заканчивает
validation и сохраняет последний чекпоинт независимо от `--save-every`.
В управляемом запуске финальное сэмплирование выполняет отдельный этап;
обычный CLI-режим обучения сохраняет прежнее поведение. Эпохи должны быть
достаточно короткими, чтобы укладываться во время штатной остановки.

Отмена исключает запуск очереди следующих этапов. Если процесс не отвечает,
после установленного срока завершается он и его потомки; уже записанные
чекпоинты сохраняются. Принудительная остановка обучения отменяет финализацию.
Автоматического перезапуска, изменения рецепта и ожидания маркера от агента нет.
Контроллер ограничивает также финализацию и записывает превышение дедлайна.

В Windows окно скрыто, дерево процессов этапа контролируется через Job Objects.
Завершение само по себе не отправляет сообщение в чат — результат нужно
забрать позже. Выключение, сон компьютера или ограничения родительского процесса
могут прервать работу. `status` показывает устаревший heartbeat, не выдавая
прерванный запуск за успешно завершённый.

### TBPTT с переносом состояния

Корпус сэмплируется окнами по `span = seq_len × state_carry`, которые
обрабатываются как `state_carry` подчанков по `seq_len` токенов. Скрытое
состояние и буфер свёртки **переносятся** между подчанками, но
**отсоединяются** от графа, что ограничивает память GPU. Эффективный
обучающий контекст — `span` токенов, а глубина градиента — `seq_len`.

Одна итерация (`step`) обрабатывает `batch_size × span` токенов. Параметры
обновляются один раз за `--grad-accumulation` итераций.

### Функция потерь

Кросс-энтропия нормализуется по валидным целевым токенам всей группы
накопления градиентов. Суммы лоссов делятся на максимальное число позиций;
перед clipping градиенты пересчитываются множителем
`max_target_positions / valid_target_tokens`. Так маска диалогов не искажает
вес целевых токенов. Без маскирования результат эквивалентен обычной средней
кросс-энтропии.

### Маска лосса (`--loss-mask`, включена по умолчанию)

Если найдены теги диалогов (только BPE), лосс считается лишь для токенов:

- **после** `<|bot|>` (текст ответа);
- токен `<|end|>` (чтобы модель училась заканчивать ответ).

Токены пользователя, системные инструкции и сами теги ролей исключаются.
Доля исключённых токенов печатается при старте.

### Диалоговые якоря (`--dialogue-anchor-ratio`, по умолчанию `0.7`)

Эта доля окон каждого батча начинается **ровно с** `<|user|>`, остальные —
случайные. Так модель чаще видит начала диалогов и учится формату «вопрос →
ответ». Якоря строятся независимо для обучения и валидации. Без диалогов
сэмплирование полностью случайное.

### Оптимизаторы

**AdamW (`--optimizer adamw`)** использует `betas=(0.9, 0.95)`; на CUDA
берётся fused-вариант, если он доступен, иначе обычная реализация.

**Muon + AdamW (`--optimizer muon`)** — гибрид:

- строго **двумерные параметры скрытых слоёв** идут в Muon (моментум плюс
  ортогонализация обновления пятью итерациями Ньютона–Шульца в bf16);
- эмбеддинги, выходной слой, смещения, RMSNorm, `h0`, `tau_mix`, трёхмерная
  свёртка и `ChunkMemory.init_slot` идут в AdamW.

У гибрида отдельное расписание для каждой части; learning rate задаются
через `--muon-lr` и `--lr`.

### Расписание learning rate

Линейный прогрев (`--warmup-steps`, измеряется в **обновлениях
оптимизатора**, а не в итерациях) сменяется косинусным спадом до
`--min-lr-ratio × lr`. Всего обновлений:
`epochs × ceil(steps_per_epoch / grad_accumulation)`.

### EMA (`--ema-decay`, по умолчанию `0.999`)

Веса усредняются скользящим средним с прогревом
(`min(decay, (1+n)/(10+n))`). После каждой эпохи валидация запускается
дважды: с обычными и с EMA-весами. Используется меньший лосс; если EMA лучше,
в лучшем чекпоинте сохраняются EMA-веса, а в лог добавляется `(EMA)`.
Обучение продолжается с обычными весами. `--ema-decay 0` отключает EMA.

### Смешанная точность (`--amp`)

`auto` выбирает bf16, если он поддерживается, иначе fp16; `fp16` включает
GradScaler; `off` или выполнение на CPU отключает смешанную точность.

### torch.compile (`--compile`)

Компилируется только один рекуррентный шаг (`_step_impl`), а не вся модель.
Режимы: `default`, `reduce-overhead` (CUDA Graphs) и `max-autotune` (не
рекомендуется для таких малых матриц: медленно и часто без выигрыша). Если
компиляция не удалась, программа откатывается на `default`, а затем на
eager-режим. Для `--generate-only` компиляция идёт в режиме оценки.
Описанный ниже `--cuda-graphs` — отдельный режим для полного шага инференса;
выберите его либо `--compile`.

### Gradient checkpointing (`--grad-checkpoint`)

Checkpointing включается на каждый вызов ячейки. Гранулярность очень мелкая,
поэтому накладные расходы могут превысить экономию: память TBPTT — это в
основном O(T) активаций по всему окну. Измерь на своих размерах, прежде чем
на него полагаться.

### Дистилляция (`--teacher-checkpoint`)

`loss = (1−α)·CE + α·T²·KL(teacher‖student)`, где `α = --kd-alpha`, а
`T = --kd-temperature`. Токенизаторы учителя и ученика должны иметь одинаковые
ID токенов и конфигурации. Учитель переносит hidden и ChunkMemory между подчанками
и сбрасывает их в начале нового span. Хвост top-k KD вычисляется в log space,
сохраняя градиенты при очень уверенных предсказаниях.

### Ранняя остановка и сохранение

- Лучший чекпоинт (по валидационному лоссу) сохраняется сразу при улучшении.
- Чекпоинт «last» записывается каждые `--save-every` эпох.
- `--patience N` останавливает обучение после `N` эпох без улучшения (`0`
  отключает).
- Превью генерации печатается каждые 5 эпох, на последней эпохе и после
  каждого улучшения.
- В конце лучшая модель генерирует финальный текст.

### Логирование

`--log-backend tensorboard` или `wandb` записывает:
`train/loss`, `train/loss_running`, `train/perplexity`, `val/loss`,
`val/loss_ema`, `val/perplexity`, `train/lr`, `train/grad_norm` и
`perf/tokens_per_sec`. Если пакета нет, программа предупреждает и продолжает
без логирования.

```bash
tensorboard --logdir runs
```

### Защита от нестабильности

Лосс и градиенты проверяются на NaN/Inf до обновлений без GradScaler, в том числе
при `--grad-clip 0`. Overflow FP16 обрабатывает GradScaler; scheduler, global step
и EMA продвигаются только после успешного обновления. Параметры семплирования
проверяются до начала обучения. Чекпоинт сначала записывается во временный файл,
затем атомарно заменяет предыдущий; недостающие папки создаются автоматически.

## Генерация и чат

### Обычная генерация

```bash
python liquid_text_model.py --generate-only \
  --prompt "Neural network" --generate 600 \
  --temperature 0.8 --top-k 50 --top-p 0.95
```

Промпт обрабатывается, а токены выбираются по одному. Порядок такой: штраф за
повторы → деление на temperature → top-k → top-p → сэмплирование. Генерация
останавливается на `<|end|>` (если он есть) или на `--generate`. Состояние и
буфер свёртки переносятся, поэтому каждый новый токен стоит O(1).

При обработке промпта выходной слой вычисляет logits только последней позиции;
все токены по-прежнему проходят рекуррентные слои. Обычный обучающий `forward`
возвращает прежний результат для всей последовательности.

| Параметр | Эффект |
|---|---|
| `--temperature` | Ниже — предсказуемее; выше — разнообразнее |
| `--top-k` | Оставить k самых вероятных токенов (0 отключает) |
| `--top-p` | Nucleus sampling: наименьшее множество с суммарной вероятностью ≥ p |
| `--repetition-penalty` | Значения > 1 снижают вероятность недавних токенов |
| `--repetition-window` | Сколько недавних токенов учитывается |

Специальные токены ролей при декодировании не печатаются.

### Разовый ответ в диалоговом формате

```bash
python liquid_text_model.py --chat --prompt "What is an LTC network?"
```

Промпт оборачивается в `<|user|>\n…\n<|bot|>\n`. Генерация останавливается на
`<|end|>` или в начале новой реплики пользователя; печатается только ответ.

### Интерактивный чат

```bash
python liquid_text_model.py --chat-repl
```

Пустая строка, `exit`, `quit` или `q` завершают чат. История диалога хранится
как текст и обрезается до `--chat-history-chars` (по умолчанию 4000) по
границе реплики.

> `--chat` и `--chat-repl` сами включают генерацию; `--generate-only` не
> нужен.

### Генерация с CUDA Graphs

```bash
python liquid_text_model.py --chat-repl --device cuda --kernel triton \
  --sequence-batching --cuda-graphs --checkpoint liquid_text_best.pt
```

`--cuda-graphs` включается явно для `--generate-only`, `--chat` и `--chat-repl`.
Захватывается полный проход одного токена: свёртка, проходы liquid-стека, FFN,
выход и обновления ChunkMemory. Обработка промпта и сэмплирование сохраняют
прежний порядок, включая расход RNG при одинаковом seed, стоп-токены и штраф
повторений. Поддерживаются Torch и Triton; сочетание с `--compile` запрещено.
Этот режим не применяется к обучению.

Первый вызов прогревает и захватывает нужные переходы, поэтому короткий первый
запрос может замедлиться. Следующие запросы переиспользуют до четырёх графов
для одной конфигурации форм и точности. Каждый промпт сбрасывает состояния
сессии. Обычные обновления весов, перенос устройства/типа и изменения
поддерживаемых настроек выполнения сбрасывают кэш. На CPU или при неподдерживаемом
захвате используется eager; невосстановимые ошибки CUDA/replay передаются
вызывающему коду. CLI печатает счётчики, позволяющие отличить replay от отката.

В Python доступны `model.set_cuda_graphs(True)`, `model.cuda_graph_stats()` и
`model.clear_cuda_graph_cache()`. Сбрасывайте кэш явно после изменений через
`.data` или собственных изменений выполнения. Графы не записываются в тензорное
состояние чекпоинта. Нужны graph-safe API генератора PyTorch (проверен 2.11);
на прежних сборках без этих API используется eager.

Замеры 21 октября 2026: RTX 5050 Laptop, PyTorch 2.11.0+cu128, LTC/Triton,
сохранённые веса на 15,17 млн параметров, три слота памяти шириной 64, чанки
по 64, один проход глубины, TF32 выключен. Семь чередующихся пар генерировали
128 токенов из BPE-промпта на восемь токенов. Медианы после прогрева включают
промпт, память, сэмплирование и декодирование текста; загрузка весов и захват
исключены.

| Точность | Eager | CUDA Graphs | Медианное ускорение в парах | Первый запрос с графами |
| --- | ---: | ---: | ---: | ---: |
| FP32 | 937 мс | 351 мс | 2,64x | 2,16 с |
| BF16 autocast | 499 мс | 207 мс | 2,40x | 1,87 с |

Первый запрос включает генерацию и прогрев/захват. Во всех парах совпали текст
и конечное состояние CUDA RNG; откатов не было. Частоты не фиксировались,
планировщик Windows вносит разброс. Это локальные замеры задержки; скорость
обучения, качество и обслуживание параллельных запросов здесь не оценивались.
BF16 используется через autocast бенчмарка; CLI-флаг `--amp` остаётся опцией
обучения.

Независимый замер случайных весов с тем же числом параметров:

```bash
python benchmark_cuda_graphs.py --hidden 768 --vocab 4096 --kernel triton --precision fp32 --pairs 7 --output runs/cuda_graphs/generation.json
```

Добавьте `--checkpoint path/to/model.pt` для поддерживаемого чекпоинта или
`--precision bf16` для autocast. Токенизация и длина промпта зависят от
чекпоинта, поэтому результаты случайных и сохранённых весов рассматриваются
отдельно.

## Triton-ядро (экспериментально)

`--kernel triton` объединяет две операции сложения/tanh LTC и их backward
первого порядка, включая градиенты двух срезов рекуррентной проекции. Для
Euler-обновления используется отдельное объединённое forward/backward-ядро.
В режиме multi-tau каждая CUDA-программа записывает только три частичные суммы
градиентов весов смешивания. Softmax весов и нормализация остаются в PyTorch.
Матричные умножения остаются на cuBLAS. Параметры модели, ключи чекпоинтов,
dropout, zoneout и поведение нормализации сохранены.
Для FP16/BF16 сохранено округление PyTorch при сложении и промежуточных
операциях backward tanh; побитовое совпадение разных бэкендов не обещается.

Требования: CUDA, совместимый с установленным PyTorch пакет Triton и параметры
`--gate-mode ltc`. При выборе Triton используется eager
recurrent step вместо `torch.compile`; перед длительным обучением сравни
tokens/sec всей модели в обоих режимах. Проверь ядро командой
`--selftest-triton`, затем запусти `python benchmark_triton_tail.py --batch-size 64
--hidden-size 384 --dtype bf16`. Микробенчмарк охватывает только LTC-хвост и не
заменяет замер производительности всего обучения. Selftest проверяет forward и
завершается кодом 2 при численном расхождении. Для mixed dtype и градиентов всей
модели запусти `python tests/check_triton_mixed.py --output runs/triton_correctness.json`,
для скорости модели — `benchmark_gpu.py`. На Windows проверен `triton-windows 3.8.0.post28`.

## Чекпоинты, возобновление и совместимость

### Что хранит чекпоинт

Веса модели, состояния оптимизатора/планировщика/GradScaler/EMA, эпоху,
глобальный шаг, train/validation лосс, лучший валидационный показатель,
конфигурацию запуска, **полный токенизатор** и SHA-256 корпуса.

### Возобновление

`--resume` читает `--last-checkpoint` **до** загрузки корпуса и берёт из него
порядок файлов (`shuffle_files`) и режим заголовков (`file_headers`); иначе
разбиение на train/validation сместилось бы. Архитектурные параметры
(`embedding_dim`, `hidden_size`, `gate_mode`, `memory_dim`, `memory_slots` и
другие) тоже берутся из чекпоинта. Отличия от командной строки печатаются как
`[RESUME] … (from checkpoint)`. Токенизатор восстанавливается, а не
переобучается. Изменившийся корпус приводит к предупреждению.
Доля validation и политика разбиения также восстанавливаются из чекпоинта.
Чекпоинт загружается на CPU, затем нужные тензоры переносятся на выбранное
устройство. Генерация и чат отбрасывают состояния оптимизатора и EMA, а копии
весов чекпоинта освобождаются после загрузки модели.

`--epochs` — это **общее** число эпох: чтобы дообучить модель, уже прошедшую 20
эпох, ещё на 40, укажи `--epochs 60`.

Если состояние оптимизатора или планировщика несовместимо (например, из-за
смены `--optimizer`), используется свежее состояние, о чём сообщается.

### Безопасная загрузка

Чекпоинты загружаются с `weights_only=True`, без выполнения произвольного
pickle-кода. Если безопасная загрузка не удалась, показывается понятная
ошибка. Для **своих доверенных файлов** можно добавить `--trust-checkpoint`;
никогда не используй его с недоверенными файлами.

### Обратная совместимость

В текущей версии resume и генерация поддерживают только чекпойнты с явным
`norm_type=rms`. Для LayerNorm и старых файлов без метаданных нормализации нужна
предыдущая версия проекта. Подменять нормализацию обученных весов нельзя.

Внутри поддерживаемого формата RMSNorm для других отсутствующих архитектурных
полей используются исторические значения (`gate_mode=ltc`, `memory_slots=0`
и так далее). Допустимые отсутствующие веса (`h0`, `tau_mix`, свёртка)
инициализируются с выводом сообщения. Ранние версии использовали **непричинную**
свёртку: для таких файлов нужна совместимая прежняя версия, а для корректной
причинной оценки — переобучение.

BPE-токенизатор v3.6 отличается от прежних версий (без пробельного префикса и
с полным байтовым алфавитом). Поддерживаемые чекпойнты используют сохранённый
токенизатор, а удалённые форматы — прежнюю совместимую версию проекта.
Для честного сравнения экспериментов обучай с нуля.

### Удалённые экспериментальные опции

NCP, FIM-преобразования, Heun и настраиваемые ODE-подшаги удалены из интерфейса
и вычислительного пути. Польза для текущей разговорной задачи не подтверждена;
это решение о составе проекта, а не вывод о бесполезности методов вообще.
Поддерживаемые чекпойнты RMSNorm с `dense`, `euler` и одним шагом сохраняют формулы
и ID токенов.
Для чекпойнтов с удалёнными формулами и возобновления FIM-рецепта выводится явная
ошибка с предложением использовать прежнюю версию. Старые результаты тестов ниже
относятся к составу проекта на момент их проведения.

## Подбор гиперпараметров и память GPU

### Размер модели

Основные потребители параметров — эмбеддинг (`vocab × embedding_dim`, он же
выходной слой при привязке весов) и рекуррентные/входные матрицы каждого
слоя, примерно `(input + hidden) × hidden × k`. Число параметров печатается
при старте как `[MODEL] Parameters`.

### Если памяти не хватает (OOM)

В порядке убывания эффективности:

1. Уменьши `--batch-size` и компенсируй `--grad-accumulation` (эффективный
   батч — их произведение).
2. Уменьши `--seq-len` (память растёт линейно с длиной подчанка; контекст
   сохраняй через `--state-carry`).
3. Включи `--amp bf16` (или `fp16`).
4. Уменьши `--hidden-size` / `--num-layers`.
5. Уменьши `--vocab-size`; логиты `batch × seq × vocab` могут быть самым
   большим тензором.
6. Уменьши `--memory-dim` или отключи память через `--memory-slots 0`.
7. `--grad-checkpoint` — в крайнем случае, и обязательно измерь эффект.

На Linux для аллокатора CUDA уже включён `expandable_segments`, чтобы
уменьшить фрагментацию.

### Если обучение медленное

Модель рекуррентная, поэтому цикл по времени последовательный:

- используй `--compile`, особенно `--compile-mode reduce-overhead`;
- увеличь `--batch-size` (рекуррентный шаг на GPU почти не зависит от
  размера батча);
- используй bf16/fp16 вместо fp32;
- измеряй `--kernel triton` и `--sequence-batching` на своей конфигурации;
- следи за `tok/s` в логе эпохи.

### Практические правила

- `--state-carry 2` при `--seq-len 128` даёт эффективный обучающий контекст в
  256 токенов. Увеличивай `--state-carry` для более длинных зависимостей и
  пробуй `--memory-slots`.
- Начинай AdamW с `--lr 2e-3`; если расходится, снизь до `1e-3` и усиль
  `--grad-clip`.
- Если валидационный лосс растёт, пока обучающий падает, увеличь объём
  данных, `--dropout`, `--zoneout` или `--weight-decay`.
- Для малых корпусов (единицы МБ) используй `--vocab-size` 4000–8000; для
  больших и диалоговых — 16000+. Слишком большой словарь программа
  автоматически уменьшает на малых корпусах.
- Логируемая перплексия — это `exp(loss)`, ограниченная `exp(20)`.

## Известные ограничения

- ChunkMemory работает при генерации и в чате, если `--memory-slots > 0`:
  читает и записывает сводки на границах `seq_len` из конфигурации чекпоинта.
  Это ограниченный FIFO-буфер, а не внимание ко всей истории; он сбрасывается
  для каждого запроса.
- При `--kd-topk > 0` масса вероятностей учителя вне top-k представляется
  хвостовым классом; `--kd-topk 0` включает полный KL по словарю, но требует
  больше памяти и вычислений.
- Triton поддерживает `ltc + euler`, инференс и backward первого порядка;
  CfC использует путь PyTorch.
- Gradient checkpointing на уровне ячейки может не экономить память.
- Последовательный Python-цикл ограничивает скорость на длинных последовательностях.
  Сравнивай CPU/GPU на нужных batch size, hidden size и backend.
- Char-токенизатор не поддерживает теги диалогов, маскирование лосса и якоря.
- Валидация — это хвост корпуса, и при малом числе файлов и
  `--no-shuffle-files` она может быть нерепрезентативной.
- Это не готовый ассистент; качество зависит от объёма и качества твоих
  данных.

## Решение проблем

Тексты сообщений приведены так, как их печатает программа (часть сообщений
русская, часть английская).

| Симптом | Причина и решение |
|---|---|
| `нет файлов корпуса` | Положи файлы с поддерживаемыми расширениями в `--data` |
| `Корпус слишком маленький` | Добавь текст или уменьши `--min-chars` |
| `Training portion is too small` / `Validation portion is too small` | Уменьши `--seq-len` или `--state-carry`, либо добавь данные |
| `CUDA was selected, but torch.cuda.is_available() == False` | Установи сборку PyTorch с CUDA или используй `--device cpu` |
| `The 'tokenizers' library is not installed — falling back to char` | `pip install tokenizers` |
| Parquet/CSV пропускается или читается неправильно | `pip install pandas pyarrow` |
| `ВНИМАНИЕ: … неуверенным определением кодировки` | Переведи файлы в UTF-8 или установи `charset-normalizer` |
| `--tie-weights requires --embedding-dim == --hidden-size` | Сделай размеры равными или добавь `--no-tie-weights` |
| `Не удалось безопасно загрузить … (weights_only=True)` | Для своего файла используй `--trust-checkpoint` |
| `Loss NaN/Inf` | Уменьши `--lr`, оставь `--grad-clip` и попробуй `--amp bf16` или `off` |
| `torch.compile failed` | Программа откатывается на eager-режим; обнови PyTorch или не указывай `--compile` |
| `triton недоступен (…)` | Причина печатается, используется путь PyTorch |
| `Optimizer/scheduler state не подошёл` | Настройки оптимизатора изменились; используется свежее состояние |
| Генерация зацикливается | Увеличь `--repetition-penalty` (1.1–1.2), уменьши `--temperature` и проверь `--top-k/--top-p` |
| Чат отвечает не по теме | Обучай на диалоговых данных; используй BPE и больше данных |
| В выводе нет тегов `<\|user\|>` | Специальные токены скрываются при декодировании; это нормально |

`python benchmark_sequence_batching.py --kernel triton --precisions fp32 bf16 fp16`.

Эксперимент с дообучением при одинаковом числе токенов показал небольшой
прирост качества при тех же 2,47 млн параметров: дообучение и равномерное
усреднение весов снизили validation NLL с 3,473696 до 3,459669, perplexity —
с 32,2557 до 31,8065. Увеличение горизонта обучения с 64 до 128 не превзошло
парный контроль ни на одном из двух seed. Это измерения на повторно используемой
validation Shakespeare, без отдельного test split. Настройки эксперимента
и скрипт `research_liquid.py` описаны в CONTRIBUTING.

Ускорение вычислений: финальная нормализация выполняется сразу для всего времени,
веса multi-tau разделяются внутри одного forward-графа, входные проекции
подготавливаются вне цикла токенов. FP32 объединяет входные головы; AMP сохраняет
раздельные GEMM и их порядок округления градиентов. Параметры, рекуррентные
уравнения и checkpoints сохранены. На конфигурации 2,47 млн параметров
(B16/T64/H384/L2/V1024, CUDA/Triton, TF32 выключен), по 15 соседним парным замерам:

| Нагрузка | Ускорение FP32 | BF16 | FP16 |
|---|---:|---:|---:|
| Forward + CE + backward + AdamW | 1,171× | 1,116× | 1,097× |
| То же с dropout=0,05, zoneout=0,1 | 1,122× | 1,109× | 1,082× |
| Промпт 128 + 32 новых токена | 1,118× | 1,124× | 1,075× |

Это медианы отношений времени внутри пар. Замеры на Windows меняются: контроль
с одинаковым кодом дал 1,035× с IQR 0,980–1,052×; генерация FP16 тоже шумная.
На трёх промптах исходный BPE-checkpoint дал одинаковые greedy-продолжения
по 64 токена до/после. SHA-256 и ключи состояния сохранены. Воспроизведение:

```bash
python benchmark_compute.py --pairs 15 --warmup 5 --precisions fp32 bf16 fp16
```

Первоначальная проверка CUDA до объединения активаций: медианы FP32
после 3 прогревов и 7 измерений (Triton объединял только хвост LTC):

| Нагрузка | CPU, 1 поток | CUDA eager | CUDA Triton | CUDA compiled |
|---|---:|---:|---:|---:|
| Шаг обучения, B=16, T=64 | 2293,1 мс | 939,9 мс | 204,9 мс | 135,8 мс |
| Генерация, prompt=128 + 32 новых токена, B=1 | 484,5 мс | 234,3 мс | 158,2 мс | 104,7 мс |

Условия: синтетические данные, одинаковые seed и начальные веса, LTC/dense Euler,
H=embedding=384, L=2, V=8000, multi-tau/local conv включены, dropout=zoneout=0,
без FFN и ChunkMemory. У CPU по одному intra-op/inter-op потоку, TF32 отключён,
CUDA синхронизируется на обеих границах замера. Шаг включает forward, CE, backward
и AdamW; генерация — обработку промпта и декодирование. Импорт, создание модели,
перенос данных и JIT-прогрев исключены. Первая компиляция может занимать минуты.
Маленькие модели могут быть быстрее на CPU; у FP16 наблюдался существенный разброс,
а AMP не обеспечил автоматического выигрыша скорости или памяти. Короткие прогоны
подтверждают работоспособность, но не качество ответов и стабильность долгого обучения.

Повторная проверка объединения активаций на той же GPU: медианное парное
ускорение относительно прежнего Triton-пути, объединявшего только хвост LTC:

| Точность | Dropout/zoneout отключены | Обычные dropout=0,05, zoneout=0,1 |
|---|---:|---:|
| FP32 | 1,048× | 1,003× |
| BF16 | 1,037× | 1,054× |
| FP16 | 1,018× | 1,031× |

Измерен полный шаг обучения при B=16, T=64, H=384, L=2, V=8000: 3 прогрева и
12 замеров каждой версии с чередованием ABBA в одном процессе. Во всех шести
случаях loss и итоговые параметры совпали после 15 обновлений. Разброс времени
остаётся существенным; результат FP32 с регуляризацией находится в пределах
шума. Подробные времена и методика приведены в CONTRIBUTING.

Команды, покрытие тестов и требования к новым измерениям описаны в
[CONTRIBUTING.md](CONTRIBUTING.md). Свежие результаты бенчмарков записываются
в игнорируемую Git папку `runs/`.

### Небольшая английская модель: локальный эксперимент

19 октября 2026 на RTX 5050 Laptop с нуля обучена LTC-модель с
**4 536 838 параметрами**: два слоя H384, BPE на 4096 токенов, связанные
эмбеддинги, multi-tau, локальная свёртка и `ffn_mult=1`. Использованы Triton,
`--sequence-batching`, FP32 с TF32, T128 и перенос состояния между двумя чанками.

Корпус включал 50 000 историй GPT-4 v2 из
[TinyStories](https://huggingface.co/datasets/roneneldan/TinyStories)
(CDLA-Sharing-1.0), 2065 обучающих пар из
[Everyday Conversations](https://huggingface.co/datasets/HuggingFaceTB/everyday-conversations-llama3.1-2k)
(Apache-2.0) и 24 000 составленных учебных примеров. Обучающие, проверочные и
тестовые записи разделены до обучения; BPE обучен только на обучающей части.
Повторы коротких ответов меняли веса выборки, сохраняя границы наборов.

| Финальная независимая проверка | После обучения тексту | После обучения ответам |
|---|---:|---:|
| Точные ответы, 200 сбалансированных учебных задач | 166/200 (83%) | 178/200 (89%) |
| Арифметическая часть | 1/28 | 8/28 |
| Perplexity историй, 256 историй / 52 490 целевых токенов ответа | 6,662 | 7,246 |

Ошибка текста измерена в непересекающихся окнах по 256 токенов со сбросом
состояния между окнами. Учебные задачи используют новые сочетания параметров
знакомых шаблонов; это не оценка универсального ассистента. В свободном диалоге
модель часто отвечает не по теме и выдумывает сведения, арифметика остаётся слабой.

Обучение тексту завершило 3600 обновлений: первые 700 с batch 64, далее 256.
Обучение ответам остановлено после 1100 сохранённых обновлений из-за ухудшения
проверочных результатов; для основной модели выбраны ранние веса после 100
обновлений. Точность ответов и perplexity историй сравнивались на проверочной
части до открытия финального теста.

Экспортированная модель занимает около **18,3 МБ** вместе с токенизатором.
Прогретая генерация показала **165,6 нового токена/с на CUDA/Triton** и
**127,7 на CPU/torch**: B1, 29 токенов запроса и 64 принудительных greedy-токена,
два прогрева, пять повторов, один поток CPU, без времени загрузки и остановки по
EOS; частоты и мощность GPU не фиксировались. Веса, манифесты данных и подробные локальные
результаты размещаются в игнорируемой Git папке `runs/english_small_4m/`.

## История изменений

### v3.8 — 21 октября 2026: повторные проходы, CUDA Graphs и автономные запуски

- Добавлен экспериментальный `--recurrent-passes`: общие веса liquid-стека,
  отдельные состояния во времени, FFN на последнем проходе и сохранение числа
  проходов в чекпоинте. По умолчанию остаётся один; дополнительные проходы
  требуют оценки качества.
- Добавлен опциональный `--cuda-graphs` для генерации и чата с учётом границ
  чанков памяти, изоляцией состояний запросов, ограниченным кэшем графов и
  восстановлением RNG при неудачном захвате. Семплирование остаётся обычным;
  `--compile` используется отдельно.
- Добавлены `echo_jobs.py launch/status/result/stop`, запуск по проверенному
  рецепту, управление деревьями процессов, бюджет времени с резервом на
  завершение и сохранение чекпоинта перед остановкой на границе эпохи.
  Пример рецепта требует локальных данных.
- Добавлены регрессионные тесты и парный бенчмарк полной генерации с CUDA Graphs.
  Команды, условия замеров и ограничения приведены в
  [CONTRIBUTING](CONTRIBUTING.md#tests-and-reproducible-measurements).
  Эти изменения выполнения и управления запусками не доказывают улучшение
  качества языка.
- Сохранены совместимость только с RMSNorm, ID токенизатора и имена тензоров
  чекпоинта. Отсутствие метаданных числа проходов означает один проход;
  кэш CUDA Graphs и состояние контроллера не входят в архитектуру модели.

### 20 октября 2026: имя Echo и переход только на RMSNorm

- Текущая модель названа Echo, описано планируемое семейство Pantheon.
- Основой стали RMSNorm и компактная память с учётом занятых слотов.
  Удалённые NCP, FIM-аугментация, Heun и дополнительные ODE-подшаги явно
  отклоняются; зарезервированные ID токенов сохранены. Для весов LayerNorm
  нужна более ранняя совместимая ревизия. Подробности — в разделе совместимости.

### 19 октября 2026: исправления устойчивости и проверка CUDA

- Исправлены градиенты top-k KD на насыщенных logits, обработка нечисловых
  градиентов и чтение AMP-состояния CfC через ChunkMemory.
- Ошибка записи сохраняет предыдущий checkpoint; генерация не вычисляет
  неиспользуемые logits промпта; неверные настройки семплирования отклоняются заранее.
- Добавлены CPU/CUDA regression-тесты и воспроизводимые бенчмарки без изменения
  архитектуры модели, имён параметров и архитектурных ключей checkpoint.
- На RTX 5050 Laptop проверены CUDA, Triton и компилированный путь.
- В Triton объединены forward/backward активаций LTC;
  добавлен замер полного шага с обычными dropout и zoneout.
