# Liquid LM — языковая модель на жидких нейросетях (LTC / CfC)

[English](README.md) | [Русский](README.ru.md)

Однофайловая реализация авторегрессионной языковой модели на **Liquid Neural Networks** (Liquid Time-Constant и Closed-form Continuous-time) на PyTorch. Весь проект — один файл `liquid_text_model.py`: загрузка и чистка корпуса, токенизаторы, модель, обучение, генерация, чат и вспомогательные утилиты.

Вместо self-attention модель обрабатывает текст рекуррентно: скрытое состояние слоя эволюционирует как динамическая система с обучаемыми постоянными времени. Это даёт память фиксированного размера и линейную по длине стоимость генерации.

> Текущая версия: **v3.6**. История изменений — в конце документа.

## Возможности

**Модель**
- Два типа вентиля: **LTC** (экспоненциальный интегратор ODE) и **CfC** (замкнутая форма из статьи Hasani et al., 2022).
- **Multi-tau**: три банка постоянных времени (быстрый / средний / медленный) со смешиванием через обучаемый softmax.
- Решатели подшага: **Euler** (по умолчанию) и **Heun** (RK2, второй порядок точности).
- **NCP-wiring**: рекуррентная матрица заменяется набором физически меньших блочных матриц по топологии Neural Circuit Policies — реальное сокращение параметров и FLOPs.
- **Каузальная depthwise-свёртка** (k=5) перед liquid-ядром, с переносом контекста между чанками и при генерации.
- Residual-связи между слоями, LayerNorm на выходе ячейки, zoneout, locked dropout на эмбеддингах.
- Привязка весов (**weight tying**) эмбеддинга и выходного слоя, опциональная MLP-голова.
- **ChunkMemory** — FIFO-память сводок прошлых подчанков с dot-product attention (в духе Transformer-XL).

**Данные**
- Форматы: `.txt .md .rst .log .csv .tsv .json .jsonl .parquet`.
- Автоопределение кодировки (`charset-normalizer`, с запасным перебором `utf-8 → cp1251 → cp1252 → latin-1`).
- Автоматическое преобразование диалоговых датасетов (`messages`, `conversations`, `instruction/output`, `question/answer` и др.) в единый формат с тегами ролей.
- Дедупликация файлов по хэшу содержимого, детерминированное перемешивание файлов, ограничение размера файла.
- Токенизаторы: **byte-level BPE** (библиотека `tokenizers`) и **посимвольный**.

**Обучение**
- Truncated BPTT с переносом состояния между подчанками (`--state-carry`).
- Градиентное накопление, clipping, cosine-расписание с warmup.
- Оптимизаторы: **AdamW** (fused на CUDA) и гибрид **Muon + AdamW**.
- **EMA** весов, автоматический выбор лучшего из «обычных» и EMA-весов на валидации.
- Смешанная точность (bf16 / fp16 с GradScaler), `torch.compile` рекуррентного шага, gradient checkpointing.
- **Маскирование loss**: в диалогах учится только ответ бота и маркер конца примера.
- **Якоря диалогов**: часть батча стартует ровно с тега `<|user|>`.
- Дистилляция знаний (KD) из чекпоинта-учителя.
- Логирование в TensorBoard / Weights & Biases (опционально).
- Resume с восстановлением оптимизатора, расписания, EMA и scaler.

**Инференс**
- Sampling с температурой, top-k, top-p и штрафом за повторы.
- Одиночный чат-запрос и интерактивный REPL с историей.
- Опциональное fused Triton-ядро для хвоста ltc-подшага (только инференс, CUDA).

## Быстрый старт

1. Положите тексты в папку `data/` (подпапки допускаются):

   ```
   data/
   ├── books/
   │   ├── book1.txt
   │   └── book2.txt
   └── dialogs.jsonl
   ```

2. Запустите обучение с настройками по умолчанию:

   ```bash
   python liquid_text_model.py --data data
   ```

3. Сгенерируйте текст лучшей моделью:

   ```bash
   python liquid_text_model.py --generate-only --prompt "Однажды" --generate 500
   ```

4. Поговорите с моделью (если обучали на диалогах):

   ```bash
   python liquid_text_model.py --chat-repl
   ```

> Минимальный размер корпуса — **1000 символов** (`--min-chars`). Для осмысленной генерации нужны мегабайты текста; корпус в несколько килобайт годится только как проверка, что всё запускается.

## Подготовка данных

### Поиск файлов

Программа рекурсивно обходит папку `--data` и берёт файлы с поддерживаемыми расширениями. Игнорируются каталоги `.git`, `__pycache__`, `node_modules`, `.venv`, `venv`, `.idea`, `.vscode`, `.mypy_cache`, `.pytest_cache`.

Если папки нет, она создаётся, а затем программа сообщает, что корпус пуст.

### Обработка каждого файла

1. Пропуск файлов больше `--max-file-mb` (если параметр > 0) и пустых файлов.
2. Чтение с учётом формата (см. таблицу ниже).
3. Очистка текста: нормализация переводов строк (`\r\n`, `\r` → `\n`), обрезка пробелов в конце строк, схлопывание 3+ пустых строк в одну пустую.
4. Дедупликация: файлы с полностью идентичным очищенным содержимым используются один раз.
5. Склейка в общий корпус. Если включён `--file-headers`, между файлами вставляются строки `===== имя_файла =====` (по умолчанию выключено).

В конце печатается статистика: сколько файлов найдено и использовано, объём по расширениям, сколько пропущено (слишком большие, пустые, дубли), а также список файлов, прочитанных с неуверенной кодировкой.

### Поддерживаемые форматы

| Расширение | Как читается |
|---|---|
| `.txt .md .rst .log` | Как текст, кодировка определяется автоматически |
| `.json` | Список или объект. Диалоговые структуры превращаются в формат с тегами, остальное — извлекается текст по ключам `text/content/article/body/document` |
| `.jsonl` | Одна JSON-запись на строку; те же правила; нераспознанные строки добавляются как есть |
| `.csv .tsv` | Через pandas: если есть пара колонок «вопрос–ответ» — диалог, иначе текстовая колонка |
| `.parquet` | Аналогично таблицам (нужны `pandas` + `pyarrow`) |

Без `pandas` csv/tsv читаются как обычный текст, а parquet пропускается.

### Диалоговый формат

Диалоги приводятся к единому виду с четырьмя специальными тегами:

| Тег | Значение |
|---|---|
| `<\|user\|>` | реплика пользователя |
| `<\|bot\|>` | ответ бота |
| `<\|system\|>` | системная инструкция |
| `<\|end\|>` | конец примера |

Пример одного обучающего примера в корпусе:

```
<|user|>
Что такое жидкая нейросеть?
<|bot|>
Это рекуррентная сеть, состояние которой описывается дифференциальным уравнением.
<|end|>
```

Распознаваемые структуры входных данных:

**Список сообщений** (формат OpenAI-подобных датасетов):
```json
{"messages": [
  {"role": "system", "content": "Отвечай кратко."},
  {"role": "user", "content": "Привет"},
  {"role": "assistant", "content": "Здравствуйте!"}
]}
```

**Формат `conversations`** (ShareGPT-подобный):
```json
{"conversations": [
  {"from": "human", "value": "Привет"},
  {"from": "gpt", "value": "Здравствуйте!"}
]}
```

**Пары «вопрос–ответ»** — проверяются по порядку:

| Ключ вопроса | Ключ ответа |
|---|---|
| `instruction` | `output` |
| `instruction` | `response` |
| `question` | `answer` |
| `prompt` | `response` |
| `prompt` | `completion` |
| `input` | `output` |

Если рядом есть непустое поле `input` (формат Alpaca), оно дописывается к вопросу с новой строки.

Соответствие ролей: `user`, `human` → `<|user|>`; `assistant`, `gpt`, `bot`, `model` → `<|bot|>`; `system` → `<|system|>`. Неизвестная роль трактуется как пользователь.

### Разбиение на train / validation

- Валидационная часть — **хвост** токенизированного корпуса, размер задаётся `--val-split` (по умолчанию `0.1`, допустимо `0.01–0.5`).
- Чтобы хвост не состоял систематически из «последних по алфавиту» файлов, включено `--shuffle-files` (по умолчанию да): файлы упорядочиваются по SHA-256 от относительного пути. Порядок детерминирован.
- Оба сплита должны быть длиннее `seq_len × state_carry + 2` токенов, иначе будет ошибка.
- BPE-токенизатор учится **только на train-части** — нет утечки словаря из валидации.

## Токенизаторы

### BPE (`--tokenizer bpe`, по умолчанию)

- Byte-level BPE: любой символ Unicode кодируется без `<unk>` (в словарь заведены все 256 байт).
- Префиксный пробел отключён: текст кодируется и декодируется без добавочных пробелов.
- Специальные токены: `<unk>`, `<pad>`, `<|user|>`, `<|bot|>`, `<|system|>`, `<|end|>`.
- Размер словаря задаётся `--vocab-size` (по умолчанию 8000, минимум 300). Для маленьких корпусов он **автоматически уменьшается**: потолок = `max(300, оценка_токенов / 20)`, где оценка = `символов / 4`.
- Большие корпуса кодируются кусками по ~2 млн символов с разрезом по границе `\n\n`, чтобы не упираться в память.
- Без установленной библиотеки `tokenizers` программа откатывается на char и сообщает об этом.

### Char (`--tokenizer char`)

- Словарь — все различные символы корпуса (по всему корпусу, не только по train).
- Неизвестные при инференсе символы заменяются пробелом.
- Диалоговые теги не являются отдельными токенами → маска loss, якоря диалогов и стоп-токены **не работают**. Для диалогов используйте BPE.

Токенизатор сохраняется внутри чекпоинта, отдельных файлов словаря не требуется.

## Архитектура модели

### Общая схема

```
токены
  │
  ▼
Embedding ──► LockedDropout
  │
  ▼
[опц.] каузальная depthwise-свёртка k=5  (x = x + conv(x))
  │
  ▼
┌──────────────── для каждого шага t ────────────────┐
│  слой 1: LiquidCell(h1, x_t)  ──►  h1'              │
│  x = x + h1'     (residual, если включено)          │
│  слой 2: LiquidCell(h2, x)    ──►  h2'              │
│  x = x + h2'                                        │
│  ...                                                │
│  final LayerNorm(x)                                 │
└─────────────────────────────────────────────────────┘
  │
  ▼
Readout (Linear или MLP-голова; веса можно связать с Embedding)
  │
  ▼
логиты (vocab_size)
```

Обработка идёт по времени в цикле Python: состояние каждого слоя обновляется токен за токеном. Проекции, зависящие только от входа `x` (но не от `h`), считаются **один раз на всю последовательность** до цикла.

### LiquidCell — режим `ltc` (по умолчанию)

Ячейка моделирует линейную ODE с входозависимой постоянной времени:

```
dh/dt = (candidate − h) / τ
candidate = tanh(W_x·x + W_h·h)
τ         = softplus(MLP([x, h])) + min_tau        (min_tau = 0.05)
```

Внутри подшага `candidate` и `τ` «замораживаются», и ODE решается точно:

```
decay = exp(−dt / τ)
h_new = decay · h + (1 − decay) · candidate
```

Это экспоненциальный интегратор — устойчивый при любых `dt` и `τ > 0`.

**Подшаги (`--ode-unfolds N`).** Один такт `dt=1` делится на `N` подшагов `dt/N`. Больше подшагов — точнее аппроксимация ODE, но линейно дороже.

**Решатель (`--ode-solver`).**
- `euler` — `candidate`/`τ` оцениваются один раз в начале подшага.
- `heun` — predictor-corrector (RK2): подшаг считается дважды (в начале и в спрогнозированном конце), значения усредняются. Второй порядок точности ценой ~2× вычислений на подшаг; часто позволяет уменьшить `--ode-unfolds` при том же качестве.

**Multi-tau (`--multi-tau`, по умолчанию да).** Выход `tau_net` утраивается, получаются три банка:

| Банк | Формула | Смысл |
|---|---|---|
| fast | `softplus(r₀ − 2) + 0.05` | быстрая динамика |
| medium | `softplus(r₁) + 0.01` | средняя |
| slow | `softplus(r₂ + 2) + 0.001` | медленная, долгая память |

Итоговая `τ = Σ wᵢ · τᵢ`, где `w = softmax(tau_mix)` — три обучаемых общих (не по-канальных) веса.

### LiquidCell — режим `cfc`

Closed-form формула из Hasani et al., *Closed-form Continuous-time Neural Networks* (Nature Machine Intelligence, 2022). Явного ODE нет: сеть напрямую параметризует решение.

```
ff1 = tanh(W₁ₓ·x + W₁ₕ·h)
ff2 = tanh(W₂ₓ·x + W₂ₕ·h)
t   = sigmoid(t_a · dt + t_b)           # t_a, t_b — функции [x, h]
h_new = ff1 · (1 − t) + t · ff2
```

Меньше индуктивного смещения «к затуханию», больше свободы в форме траектории. `--multi-tau` и `--ode-solver` в этом режиме игнорируются (нет `τ` и ODE); `--ode-unfolds > 1` допустим — тогда интерполяция композируется на более мелких `dt`. Инициализация `time_net.bias = 0` даёт нейтральный старт `t = 0.5`.

### Выход ячейки и нормировка состояния

Новое состояние слоя — это `LayerNorm(Dropout(h))`. То есть между шагами по времени переносится **нормированное** состояние. Это сознательное проектное решение: оно стабилизирует динамику на длинных последовательностях.

**Zoneout (`--zoneout`).** Во время обучения часть элементов выхода заменяется нормированным предыдущим состоянием — регуляризация, не дающая состоянию меняться слишком резко.

### NCP-wiring (`--wiring ncp`)

Нейроны делятся на три группы: **inter**, **command**, **motor** (доли `--ncp-command-frac`, `--ncp-motor-frac`; остаток — inter). Разрешены только пути:

```
inter   → inter      (рекуррентно)
inter   → command
command → command    (рекуррентно)
command → motor
motor   → command    (обратная связь)
```

Каждый путь — **отдельная физически меньшая матрица** `nn.Linear`, а не маска поверх dense `H×H`. Маска поверх dense-матрицы в PyTorch не ускоряет вычисления (матмул всё равно считает все произведения), здесь же несуществующих связей нет ни в весах, ни в вычислениях.

При запуске печатается доля от dense, например: `ncp (рекуррентная часть ~46% от dense по параметрам/FLOPs)`.

Что **не** воспроизводится из оригинальной статьи: биофизическая полярность синапсов (reversal potentials, возбуждающие/тормозящие связи). Знак и величину весов на разрешённых связях учит градиентный спуск. В `cfc`-режиме `ff1_h` и `ff2_h` — два независимых экземпляра с одинаковой топологией. Гейтинг по времени (`tau_net` / `time_net`) остаётся dense.

### Локальная каузальная свёртка (`--local-conv`)

Depthwise `Conv1d` с ядром 5 добавляет к эмбеддингам локальный контекст из 4 предыдущих токенов: `x = x + conv(x)`.

**Свёртка строго каузальная**: паддинг только слева, выход в позиции `t` зависит от `x[t−4..t]`. Симметричный padding «подглядывал» бы будущие токены — прямая утечка ответа в loss. Чтобы контекст не обрывался на границах чанков и при посимвольной генерации, последние 4 входа сохраняются в **буфере свёртки**, который переносится как дополнительный элемент списка `hidden`.

### Residual, привязка весов, голова

- `--residual` (да): `x = x + h_new` после каждого слоя. Для первого слоя работает только при `embedding_dim == hidden_size`.
- `--tie-weights` (да): выходной слой использует матрицу эмбеддингов. Требует `embedding_dim == hidden_size`.
- `--mlp-head` (нет): вместо одного `Linear` — `Linear → GELU → Linear`.
- Начальные состояния `h0` обучаемы (по параметру на слой).

### ChunkMemory (`--memory-slots N`)

Дополнительный медленный канал памяти поверх `--state-carry`:

- В конце каждого подчанка финальное состояние последнего слоя кладётся в FIFO-буфер из `N` слотов.
- В начале следующего подчанка буфер читается dot-product attention'ом, результат подмешивается в состояние последнего слоя через обучаемый gate.
- Буфер хранит **сырые** состояния; сжатие `summarize` применяется лениво при чтении — поэтому оно реально получает градиент.
- Между подчанками буфер детачится, как и `hidden`: прямого градиента через границу чанка нет. Веса учатся полезной политике чтения/записи внутри каждого подчанка.
- Работает только при `--state-carry ≥ 2`.
- **Используется только в обучении и валидации**; `generate()` и чат эту память не подключают.

### Инициализация

Эмбеддинги — `N(0, 0.02)`; рекуррентные матрицы — ортогональные с `gain=0.99`; входные проекции — Xavier; смещение последнего слоя `tau_net` — 0.1; свёртка — Kaiming.

## Как устроено обучение

### TBPTT с переносом состояния

Из корпуса сэмплируется окно длиной `span = seq_len × state_carry`, которое обрабатывается `state_carry` подчанками по `seq_len` токенов. Скрытое состояние (и буфер свёртки) **переносится** между подчанками, но **детачится** от графа — это ограничивает память GPU. Эффективный контекст обучения — `span` токенов, градиент течёт на глубину `seq_len`.

За одну итерацию (`step`) обрабатывается `batch_size × span` токенов. Параметры обновляются раз в `--grad-accumulation` итераций.

### Функция потерь

Кросс-энтропия по следующему токену, усреднённая по **валидным** токенам. Loss каждого подчанка делится на `state_carry × размер_группы_накопления`, так что вклад усреднён корректно, в том числе в последней неполной группе эпохи.

### Маска loss (`--loss-mask`, по умолчанию да)

Если в корпусе найдены диалоговые теги (только BPE), loss считается лишь по:
- токенам **после** `<|bot|>` (текст ответа),
- токену `<|end|>` (модель учится заканчивать ответ).

Токены пользователя, системные инструкции и сами теги ролей из loss исключаются. Доля исключённых токенов печатается при старте.

### Якоря диалогов (`--dialogue-anchor-ratio`, по умолчанию 0.7)

Доля окон каждого батча стартует **ровно с позиции тега `<|user|>`**, остальные — случайные. Так модель чаще видит начало диалога и обучается формату «вопрос → ответ». Якоря строятся отдельно для train и validation. Если диалогов нет, сэмплинг полностью случайный.

### Оптимизаторы

**AdamW** (`--optimizer adamw`) — `betas=(0.9, 0.95)`; на CUDA используется fused-версия, при её недоступности — обычная.

**Muon + AdamW** (`--optimizer muon`) — гибрид:
- к строго **2D-параметрам скрытых слоёв** применяется Muon (momentum + ортогонализация обновления пятью итерациями Newton–Schulz в bf16);
- эмбеддинги, выходной слой, смещения, LayerNorm, `h0`, `tau_mix`, свёртка (3D) и `ChunkMemory.init_slot` обновляются AdamW.

Для гибрида расписание создаётся отдельно для каждой части; learning rate'ы задаются `--muon-lr` и `--lr`.

### Расписание learning rate

Линейный warmup (`--warmup-steps`, в **обновлениях оптимизатора**, не итерациях) и косинусный спад до `--min-lr-ratio × lr`. Всего обновлений: `epochs × ceil(steps_per_epoch / grad_accumulation)`.

### EMA (`--ema-decay`, по умолчанию 0.999)

Скользящее среднее весов с прогревом (`min(decay, (1+n)/(10+n))`). После каждой эпохи модель оценивается на валидации дважды — с обычными и EMA-весами. В качестве метрики берётся меньший loss; если лучше EMA, в лучший чекпоинт сохраняются именно EMA-веса (в логе пометка `(EMA)`). Затем обучение продолжается с обычными весами. `--ema-decay 0` отключает EMA.

### Смешанная точность (`--amp`)

`auto` — bf16, если поддерживается, иначе fp16; `fp16` включает GradScaler; `off` или CPU — отключено.

### torch.compile (`--compile`)

Компилируется один рекуррентный шаг (`_step_impl`), а не вся модель. Режимы: `default`, `reduce-overhead` (CUDA Graphs), `max-autotune` (не рекомендуется для таких маленьких матриц — долго и без выигрыша). При ошибке сборки программа откатывается на `default`, а затем на eager. Для инференса (`--generate-only`) компиляция идёт в eval-режиме.

### Градиентный чекпоинтинг (`--grad-checkpoint`)

Включается на уровне каждого вызова ячейки. Гранулярность очень мелкая, поэтому накладные расходы могут превысить экономию: реальная память в TBPTT уходит на O(T) активаций по длине окна. Измеряйте на своих размерах, прежде чем полагаться на него.

### Дистилляция (`--teacher-checkpoint`)

`loss = (1−α)·CE + α·T²·KL(student‖teacher)`, где `α = --kd-alpha`, `T = --kd-temperature`. Словарь учителя должен совпадать со словарём ученика. Учитель вызывается **без переноса hidden** между подчанками, поэтому его soft-labels для 2-го и далее подчанков менее информативны.

### Ранняя остановка и сохранение

- Лучший чекпоинт (по валидации) сохраняется сразу при улучшении.
- «Последний» чекпоинт пишется каждые `--save-every` эпох.
- `--patience N` — остановка после `N` эпох без улучшения (0 — отключено).
- Каждые 5 эпох, в последнюю эпоху и при каждом улучшении печатается **превью** генерации.
- По завершении лучшая модель генерирует итоговый текст.

### Логирование

`--log-backend tensorboard` или `wandb`; метрики: `train/loss`, `train/loss_running`, `train/perplexity`, `val/loss`, `val/loss_ema`, `val/perplexity`, `train/lr`, `train/grad_norm`, `perf/tokens_per_sec`. Если пакет не установлен — предупреждение и работа без логирования.

```bash
tensorboard --logdir runs
```

### Защита от нестабильности

Проверка на NaN/Inf в loss (при fp16 пропуски обрабатывает GradScaler), clipping градиента по норме (`--grad-clip`, 0 — выключено), прерывание с понятной ошибкой при расходимости.

## Генерация и чат

### Обычная генерация

```bash
python liquid_text_model.py --generate-only \
  --prompt "Нейронная сеть" --generate 600 \
  --temperature 0.8 --top-k 50 --top-p 0.95
```

Прогоняется промпт, затем токены выбираются по одному. Применяются по порядку: штраф за повторы → деление на температуру → top-k → top-p → сэмплирование. Остановка по `<|end|>` (если он есть в словаре) или по лимиту `--generate`. Используется перенос состояния и буфера свёртки, поэтому каждый новый токен стоит O(1).

| Параметр | Эффект |
|---|---|
| `--temperature` | ниже → предсказуемее, выше → разнообразнее |
| `--top-k` | оставить k самых вероятных токенов (0 — выкл.) |
| `--top-p` | nucleus sampling: наименьший набор с суммарной вероятностью ≥ p |
| `--repetition-penalty` | > 1 снижает вероятность недавних токенов |
| `--repetition-window` | сколько последних токенов учитывать |

Специальные токены (теги ролей) при декодировании не выводятся.

### Разовый ответ в диалоговом формате

```bash
python liquid_text_model.py --chat --prompt "Что такое LTC-сеть?"
```

Промпт оборачивается в `<|user|>\n…\n<|bot|>\n`, генерация останавливается на `<|end|>` или на начале новой реплики пользователя; печатается только ответ.

### Интерактивный чат

```bash
python liquid_text_model.py --chat-repl
```

Пустая строка, `exit`, `quit`, `q` или `выход` — выход. История диалога хранится в виде текста и обрезается до `--chat-history-chars` (по умолчанию 4000) по границе реплики.

> Флаги `--chat` и `--chat-repl` сами включают режим генерации, `--generate-only` указывать не нужно.

### Какую модель берёт генерация

Файл из `--checkpoint` (по умолчанию `liquid_text_best.pt`). Архитектура и токенизатор читаются из самого чекпоинта.

## Triton-ядро (экспериментально)

`--kernel triton` заменяет хвост ltc-подшага (softplus по банкам, смешивание, `exp`, обновление `h`) одним fused-ядром вместо примерно восьми поэлементных операций PyTorch. Матмулы остаются на cuBLAS.

Условия работы:
- только **инференс** (`generate`, чат, `evaluate`) — у ядра нет backward;
- только CUDA и установленный `triton`;
- только `--gate-mode ltc --ode-solver euler`.

В остальных случаях программа печатает причину и остаётся на PyTorch. Перед использованием проверьте корректность и скорость на своей видеокарте:

```bash
python liquid_text_model.py --selftest-triton
```

Тест сверяет ядро с PyTorch-путём (одиночный и multi-tau режимы, неравномерные веса банков, «жёсткие» входы), допуск `1e-4`, и измеряет время шага.

## Чекпоинты, resume и совместимость

### Что хранится в чекпоинте

Веса модели, состояния оптимизатора, расписания, GradScaler и EMA; эпоха, глобальный шаг, train/val loss, лучший val; конфигурация запуска; **токенизатор целиком**; SHA-256 корпуса.

### Resume

`--resume` читает `--last-checkpoint` **до** загрузки корпуса и берёт из него порядок файлов (`shuffle_files`) и режим заголовков (`file_headers`) — иначе сдвинулся бы train/val-сплит. Параметры архитектуры (`embedding_dim`, `hidden_size`, `gate_mode`, `wiring`, `memory_slots` и др.) также берутся из чекпоинта; расхождения с командной строкой печатаются как `[RESUME] … (из checkpoint)`. Токенизатор восстанавливается из чекпоинта, а не переучивается. Если корпус изменился, будет предупреждение.

`--epochs` задаёт **общее** число эпох: чтобы дообучить модель, обученную 20 эпох, ещё на 40, укажите `--epochs 60`.

Если состояние оптимизатора или расписания не подошло (например, сменили `--optimizer`), используются свежие, и об этом сообщается.

### Безопасная загрузка

Чекпоинты загружаются с `weights_only=True`, то есть без исполнения произвольного pickle-кода. Если безопасная загрузка не удалась, будет понятная ошибка. Для **своих** доверенных файлов можно добавить `--trust-checkpoint`. Никогда не используйте его с файлами из непроверенных источников.

### Обратная совместимость

Чекпоинты старых версий загружаются: для отсутствующих параметров архитектуры подставляются прежние значения (`gate_mode=ltc`, `ode_solver=euler`, `wiring=dense`, `memory_slots=0` и т.д.), а новые веса (`h0`, `tau_mix`, свёртка) инициализируются заново с сообщением. Важное замечание: ранние версии содержали **некаузальную** свёртку, поэтому старые веса с `local_conv` стоит переобучить.

Токенизатор BPE версии v3.6 отличается от более ранних (нет префиксного пробела, полный байтовый алфавит). Старые чекпоинты продолжают работать со своим собственным токенизатором, но для честного сравнения экспериментов переобучайте с нуля.

## Подбор гиперпараметров и память GPU

### Размер модели

Основные потребители параметров: эмбеддинг (`vocab × embedding_dim`, он же выходной слой при tying), рекуррентные и входные матрицы каждого слоя (порядка `(input + hidden) × hidden × k`). Число параметров печатается при старте (`[MODEL] Parameters`).

### Если не хватает памяти (OOM)

В порядке убывания эффективности:
1. Уменьшить `--batch-size`, компенсируя `--grad-accumulation` (эффективный батч = произведение).
2. Уменьшить `--seq-len` (память растёт линейно с длиной подчанка; контекст при этом можно сохранить через `--state-carry`).
3. Включить `--amp bf16` (или `fp16`).
4. Уменьшить `--hidden-size` / `--num-layers`.
5. Уменьшить `--vocab-size` — логиты `batch × seq × vocab` бывают самым большим тензором.
6. Попробовать `--wiring ncp`.
7. `--grad-checkpoint` — как последнее средство и с замером.

На Linux уже включён `expandable_segments` для аллокатора CUDA, что снижает фрагментацию.

### Если обучение медленное

Модель рекуррентна, поэтому цикл по времени последователен. Ускорение:
- `--compile` (особенно `--compile-mode reduce-overhead`);
- увеличить `--batch-size` — рекуррентный шаг почти не зависит от размера батча на GPU;
- bf16/fp16 вместо fp32;
- `--ode-unfolds 1` и `--ode-solver euler` (каждый подшаг и Heun стоят дороже);
- следить за `tok/s` в логе эпохи.

### Ориентиры

- `--state-carry 2` и `--seq-len 128` дают эффективный контекст обучения 256 токенов; для длинных зависимостей увеличивайте `--state-carry` (дёшево по памяти) и пробуйте `--memory-slots`.
- Стартовый `--lr 2e-3` для AdamW; при расходимости снижайте до `1e-3` и усиливайте `--grad-clip`.
- Если validation loss растёт при падающем train loss — это переобучение: увеличьте данные, `--dropout`, `--zoneout`, `--weight-decay`.
- `--vocab-size` для небольших корпусов (единицы МБ) — 4000–8000; для больших и диалоговых — 16000+. Слишком большой словарь на маленьком корпусе программа сама уменьшит.
- Perplexity в логе считается как `exp(loss)` и ограничена сверху `exp(20)`.

## Известные ограничения

- **ChunkMemory не участвует в генерации и чате.** Модель, обученная с `--memory-slots > 0`, при инференсе работает без этой памяти — небольшое расхождение между train и inference.
- **Дистилляция** вызывает учителя без переноса состояния между подчанками.
- **Triton-ядро** — только инференс, только `ltc + euler`.
- **NCP** воспроизводит топологию связей, но не биофизику синапсов оригинальной статьи; ChunkMemory воспроизводит общую идею M-CfC, но не формулы из неё.
- **Gradient checkpointing** на уровне одной ячейки может не давать выигрыша.
- Последовательная по времени обработка медленнее трансформера на длинных батчах при обучении (при генерации — наоборот, быстрее).
- Char-токенизатор не поддерживает диалоговые теги, маску loss и якоря.
- Валидация — это хвост корпуса; при малом числе файлов и отключённом `--shuffle-files` она может быть нерепрезентативной.
- Модель не является готовым «ассистентом»: качество определяется объёмом и качеством ваших данных.

## Решение проблем

| Симптом | Причина и решение |
|---|---|
| `В data нет файлов корпуса` | Положите файлы с поддерживаемыми расширениями в `--data` |
| `Корпус слишком маленький` | Нужно минимум `--min-chars` символов; добавьте текст или уменьшите порог |
| `Train/Validation часть слишком маленькая` | Уменьшите `--seq-len` или `--state-carry`, либо добавьте данные |
| `Выбран CUDA, но torch.cuda.is_available() == False` | Установите сборку PyTorch с CUDA или используйте `--device cpu` |
| `Библиотека 'tokenizers' не установлена — откат на char` | `pip install tokenizers` |
| Parquet/CSV читаются как мусор или пропускаются | `pip install pandas pyarrow` |
| `ВНИМАНИЕ: … неуверенное определение кодировки` | Перекодируйте файлы в UTF-8 или установите `charset-normalizer` |
| `--tie-weights требует --embedding-dim == --hidden-size` | Сделайте размеры равными или добавьте `--no-tie-weights` |
| `Не удалось безопасно загрузить … (weights_only=True)` | Чекпоинт содержит несовместимые объекты; для своих файлов — `--trust-checkpoint` |
| `Loss NaN/Inf` | Снизьте `--lr`, оставьте `--grad-clip`, попробуйте `--amp bf16` или `off` |
| `torch.compile не заработал` | Продолжается в eager-режиме; обновите PyTorch или не используйте `--compile` |
| `triton недоступен (…)` | Причина печатается; используется PyTorch-путь |
| `Optimizer/scheduler state не подошёл` | Сменились параметры оптимизатора; продолжается со свежими состояниями |
| Генерация зацикливается | Увеличьте `--repetition-penalty` (1.1–1.2), снизьте `--temperature`, проверьте `--top-k/--top-p` |
| Чат отвечает «не по теме» | Модель не обучена на диалогах или данных мало; используйте BPE и диалоговые датасеты |
| В выводе нет тегов `<\|user\|>` | Специальные токены скрываются при декодировании — это нормально |

### Как добавить собственную архитектурную опцию

1. Добавьте аргумент в `build_parser()`.
2. Передайте его в `LiquidLanguageModel` / `LiquidCell`.
3. Добавьте ключ в `ARCH_KEYS` и значение по умолчанию для старых чекпоинтов в `LEGACY_ARCH_DEFAULTS` — тогда `--resume` и загрузка старых файлов продолжат работать.
4. Передайте параметр в `create_model_from_config`.
